# mpc_lab: щотижневий LP (MPC) і все, що пробували навколо нього

Проміжна робота. Підсумки з числами — у [hub/tried/mpc.md](../../../hub/tried/mpc.md); тут лише код.

Агент: [agents/anastasiia_mpc_baseload](../../../agents/anastasiia_mpc_baseload), рядок у
[Formal Results](../../../hub/FORMAL_RESULTS.md): 0.762 на Small і 0.428 на Full. Моделі на правилах дають більше на обох.

| файл | що робить |
| --- | --- |
| `vendor_mpc.py` | копіює потрібні модулі shockbench-flow в `sbfv/` поруч з агентом (на сервері пакет імпортувати не можна); запускати після оновлення пакета |
| `mpc_foresight.py` | стенд: скільки дало б планувальнику знання кожної частини майбутнього |
| `package_baselines.py` | RSS базових політик із самого пакета (`greedy_lp`, `mpc_det`, `mpc_scen`) |
| `variants.py` | сітка `params.json` для агента з парною різницею до бази |

## planners/

Скрипти окремих експериментів над планувальником, як їх лишили після прогонів (не чищені, лінтер їх не перевіряє).
Запускаються з кореня репозиторію: `uv run python lab/anastasiia/mpc_lab/planners/<скрипт>.py`. `BRIEF.md` — постановка,
з якою вони писалися; шляхи в ній старі (`team/experiments/`).

| файл | що це | результат |
| --- | --- | --- |
| `planner_B.py` | правило «спершу базове навантаження» цілими змінними у щотижневому вікні (`milp_plan`, `zfix_plan`); програвання плану в симуляторі (`scratch`, `playback`) | основа того, що зараз в агенті |
| `planner_D.py` | план на весь епізод із точними правилами як цілочислова задача; стеля і програвання плану наосліп | 0.91 за планом, 0.83 у симуляторі (16 епізодів) |
| `planner_D2.py` | суворіше формулювання того самого правила у щотижневому вікні | за 10 с краще за `planner_B`, в агента не перенесено |
| `planner_A.py` | обмежити енергію фабрик «плановим залишком» і розв'язати ще раз | не допомогло |
| `planner_C.py` | ціни, межі запасу палива, «лагодження» порушень | не допомогло |
| `planner_F.py`, `F_oracle_regimes.py` | зафіксувати режим кожної системи наперед без цілих змінних | не допомогло |
| `planner_G.py` | «зіграй і виправ»: зафіксувати в LP те, що зробив симулятор | не допомогло |
| `planner_H.py` | точні правила автоматичних кроків (паливо, запуск партій, пакування) цілими змінними, з перевіркою проти симулятора | план збігається із симулятором, але щотижневий планувальник гірший, ніж з одним правилом про струм |
| `diag_chain.py`, `diag_fab.py` | план на весь епізод проти симулятора: відправлення, протоки, генерація, партії, пакування, попит | |
| `week_ahead.py` | щотижневий план на 1–8 тижнів уперед проти того, що сталося | |
| `plan_vs_exec.py`, `plan_lag.py` | те саме за компонентами вартості | |
| `rules_bound.py` | LP на весь епізод з правилами пакета і без них | |
| `*.log` | сирі результати прогонів, з яких узято числа в `hub/tried/mpc.md` | |
