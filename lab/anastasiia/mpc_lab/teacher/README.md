# Привілейований вчитель для imitation learning

`teacher_gen.py` генерує пари (спостереження тижня, дія вчителя) на НАВЧАЛЬНИХ епізодах (root 555, записаний у
зайняті в CLAUDE.md). Вчитель легально знає майбутнє епізоду; студент (GNN) бачить лише спостереження.

```
uv run python lab/anastasiia/mpc_lab/teacher/teacher_gen.py generate --task=small --entropy=555 --episodes=32 --start=0 \
    --tl=60 --ls_budget=5000 --n_jobs=2
uv run python lab/anastasiia/mpc_lab/teacher/teacher_gen.py report --task=small --entropy=555
```

Roots 0/111/222/333/444 скрипт відмовляється використовувати.

## Рецепт вчителя (на епізод)

1. **MILP-план** на весь епізод з точними правилами симулятора `base,fuel,lots` (`planner_H.solve_full` у циклі
   constraint generation, `tl` с на раунд, `gap` 1e-3, до `rounds` = 8 раундів). **План кожного раунду
   програється в Env, береться найкращий за зіграним J**, а не останній. Так виходить, бо пізні раунди на важких
   епізодах часто обриваються за часом з великим gap. Раунд без інкумбента зупиняє цикл. Якщо невдалим виявився вже
   раунд 0, запасний варіант — LP плану без правил (`status = lp_fallback`).
2. **Зіграний план** — тижневі wire-дії `lp_common.week1_action` (`planner_LS.plan_actions`). Кешуються в
   `stage/ep<n>_plan.pkl.gz`, тож після рестарту MILP не розв'язується знову.
3. **Локальний пошук** (`planner_LS`: ходи ×1.5, drop, зсуви ±1/±2, half, ×2), строге перше покращення, оцінка
   швидким реплеєм (`planner_LSF.FReplay`). Бюджет — `ls_budget` реплеїв. Пошук іде по всіх слотах: спершу
   пластини, потім паливо, далі решта, у кожній групі за qty × v. Overrides і holds на протоках лишаються такими,
   як у плані.
4. **Запис**: фінальні дії грає gymnasium-середовище (`gym.make(env_id(task), entropy=E)`,
   `reset(options={"episode": n})`, policy seed 0, без fallback). Перед кожним кроком зберігається спостереження.
   Gym J має збігтися з J реплею (`J_teacher == J_replay`). Якщо ні, у лог іде WARNING.
5. **Референси**: `sbf_starter.scoring.episode_set(task, [n], entropy=E)`. `sbf_starter` імпортується першим, тож
   кеш береться з `hub/refcache` і доповнюється ним (≈12 с на епізод).

Прогрес пишеться в `gen.log` (ця тека) після кожного кроку. Епізод, для якого вже є `ep<n>.npz`, пропускається.
Файли записуються атомарно (tmp → rename).

## Формат даних

Тека `outputs/teacher/<task>_<entropy>/`:

- `config.pkl.gz` — `agent_config(static, policy_seed=0, layout, obs)`, саме той `config`, який отримує
  `Agent.__init__` сабміту. Він однаковий для всіх епізодів задачі (static перевірено на епізодах 0 і 1 Small 555).
  Структура графа (вузли, ребра, слоти, layout) — тут.
- `ep<n>.npz` (`np.savez_compressed`; `np.load(path)` без `allow_pickle`). T — кількість тижнів (52 на Small,
  104 на Full):

| ключ | форма | dtype | що це |
| --- | --- | --- | --- |
| `obs/<поле>` | (T, *форма поля) | як у gym | спостереження тижня t (до дії), **як є** з `env.reset` / `env.step`, тобто `observation_arrays(layout, obs)`; разом із масками `*.observed`, `action_mask`, `override_mask`. На Small 112 полів (разом з масками), напр. `obs/stock.qty` (52, 59), `obs/queue_lots.qty` (52, 77, 52), `obs/messages.kind` (52, 2432) |
| `act/flows` | (T, n_slots) | float64 | дія тижня t, формат gym `flows` (Small: n_slots = 108) |
| `act/override_qty` | (T, n_override_slots) | float64 | Small: 36 |
| `act/release_mode` | (T, n_pairs) | int64 | 0 = дефолтний випуск, 1 = override, 2 = hold (Small: 14 пар) |
| `reward_cents` | (T,) | int64 | `info["reward_cents"]` тижня: −вартість, на останньому тижні плюс salvage |
| `J_teacher` | () | int64 | J вчителя в gym, центи (= −Σ reward_cents) |
| `J_replay` | () | int64 | J за швидким реплеєм (має дорівнювати `J_teacher`) |
| `J_plan_played` | () | int64 | зіграний MILP-план до локального пошуку |
| `J_claimed` | () | int64 | J, заявлений MILP для вибраного раунду (модельний) |
| `J_naive`, `J_oracle` | () | int64 | референси (naive, clairvoyant) |
| `stratum` | () | int64 | рівень шкоди 1–4 |
| `salvage_cents` | () | int64 | термінальний salvage |
| `meta` | () | str (JSON) | `json.loads(str(z["meta"]))`: параметри, статус MILP (`converged` / `round_cap` / `no_incumbent_round_k` / `lp_fallback`), історія раундів (claimed і played на кожному), вибраний раунд, статистика ходів LS, час, omega hash |

RSS епізоду: `(J_naive − J_teacher) / (J_naive − J_oracle)`. RSS набору: `package_baselines.rss` (зважено за рівнями).

## Що треба знати лоадеру студента

- Пара (`obs/*[t]`, `act/*[t]`) — це спостереження тижня t+1 (week = t+1) і дія, яку вчитель на нього зіграв.
  Наступне спостереження вже залежить від цієї дії: дані on-policy для вчителя.
- Спостереження зберігаються сирими, тобто так, як `Agent.act(observation)` бачить їх на сервері. Нормування й
  побудова графа — справа студента. Поля з паддингом (`pipeline.*`, `messages.*`, `pending_prohibitions.*`,
  `wip.*`, `closure_end.*`) мають маски `*.observed`: дійсні лише рядки, де маска = 1.
- `act/flows[t, s]` > 0 лише там, де `obs/action_mask[t, s]` = 1. `override_qty` має сенс лише там, де
  `release_mode` пари = 1 (пара override-слота: `config["layout"]["release_pairs"]` і
  `config["static"]["override_slots"]`). Override і hold вчитель бере з MILP-плану, LS їх не змінює.
- Дії вчителя відкритопетлеві: вони знають майбутнє (місткості ребер, закриття). Студент вчиться «діяти як той,
  хто знав». Compounding errors лікуються DAgger-ом: переплан вчителя від станів студента (`replan_curve`).
- Масштаб: ненульові `flows` на Small від ~30 до ~1.3e5 одиниць (5–95 %, медіана 1.8e4; еп. 0) товару і різні для різних товарів, тож потрібне
  нормування за слотом/товаром (наприклад, на нормальний план або на `obs/graph_now.u`).
- Розмір: ≈0.1–0.2 МБ на епізод Small (стискаються паддинги). Один епізод — 52 пари.
- MILP з лімітом часу недетермінований (залежить від навантаження машини): повторна генерація того самого епізоду
  може дати іншу траєкторію. Детермінований лише запис наявних дій.

## Пілот (7 жовтня): Small, root 555, епізоди 0–15

Запуск: `--tl=60 --ls_budget=5000 --n_jobs=2`, поруч ішов чужий прогін на 2 ядрах. Планували 32 епізоди, але
вийшло ≈11 хв на епізод на одного воркера (MILP 439 с, LS 194 с), тож пілот зупинено після 16 епізодів (87 хв
настінного часу). Перевірено одним прогоном.

| | RSS ×16 (рівні 9/5/1/1) |
| --- | --- |
| заявлений MILP (вибраний раунд) | 0.8991 |
| зіграний план | 0.8824 |
| **вчитель (після LS 5 000)** | **0.8914** |

- LS додає в середньому 10.8 млрд USD на епізод (від 2.3 до 22.0), RSS епізоду в середньому +0.016.
- MILP: 5 епізодів зійшлися, 9 упираються в ліміт раундів (8), 2 зупинилися на раунді без інкумбента (еп. 0 і 8:
  узято найкращий зіграний із попередніх раундів). LP-fallback не знадобився жодного разу.
- Gym J збігся з J реплею в 16 із 16 епізодів. Розмір ≈0.14 МБ на епізод.
- Слабкі епізоди: 0 (0.66; MILP із gap 11–25 % за 60 с) і 8 (0.79). Тут вчителю бракує часу MILP, а не пошуку.
