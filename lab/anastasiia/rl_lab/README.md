# rl_lab: навчання з підкріпленням як поправка до правил

Перевіряли одну гіпотезу: **чи може мала мережа, навчена з підкріпленням, стабільно обійти
`anastasiia_rules_v2`.** Відповідь — **ні**, і причина знайдена не в алгоритмі.

## Головний результат: чому напрямок закритий

У кожному стані **є** корисний хід: на 600 станах Small у 600 з 600 знайдено кандидата, кращого за правила, вартого
в середньому **+0.31 %** вартості до кінця епізоду. Але **який саме хід — визначає майбутнє сценарію, а не стан**:

- кожен множник до запиту правил має **негативну** середню перевагу (−0.0070 % для 1.25, −0.0091 % для 1.6,
  −0.0147 % для 2.5 на 9282 пропозиціях кожного);
- найкраща **стала** пара (група слотів, множник) зі 147 дає +0.0036 % ± 0.0026 % — нуль у межах помилки;
- модель, навчена на **точних** мітках, запам'ятовує тренувальні епізоди (`captured` +0.97) і переносить **гірше за
  нуль** (−0.345), причому на жодній епосі утримане значення не було позитивним.

Це одним заміром пояснює всю серію: PPO зійшовся до майже сталого зсуву саме тому, що найкращий сталий зсув ≈0, а
будь-який інший від'ємний. Стеля, виміряна пошуком зі знанням майбутнього (≈0.86), причинно недосяжна, бо весь
виграш пошуку — це передбачення, а не читання стану. Узгоджується з уже відомим: `warning.score` має AUROC
0.51–0.59, оголошення справжні наполовину, «залишиться як є» — найкращий прогноз.

**Чого з цього не випливає:** що жодна форма рішення не має залежної від стану переваги. Виміряно для **множника до
запиту правил**. Для будь-якої іншої форми той самий замір (`counterfactual.py` плюс `constant_policy.py`) коштує
близько години — і це найдешевший спосіб відсікти або відкрити її **до** навчання.

Повні числа, криві й розбір — у [../../../hub/tried/rl.md](../../../hub/tried/rl.md); звіт сесії цілком —
[REPORT.md](REPORT.md).

чотири години на навчання до будь-якого заміру):

1. `constant_policy.py` на наборі з `counterfactual.py` — чи є залежна від стану перевага. Година.
2. `action_search.py` — стеля зі знанням майбутнього. Години.

## Два технічні факти, корисні будь-якому методу

- **Знімок стану симулятора точний.** `copy.deepcopy` полів `core`, `_week` і `np_random` адаптера коштує 19 мс, а
  відновлення відтворює хвіст епізоду до цента (перевірено на тижнях 1, 10 і 30). **Пропустити `_week` — значить
  зсунути епізод на тиждень і отримати правдоподібні, але хибні числа.** Разом із тим, що епізод Small грається за
  0.04 с, це дає точні контрфакти замість шумного градієнта.
- **Стан відновлюваний зі спостереження.** З 84 позицій запасу 59 є в `stock.qty`, решта 25 — усі запаси на
  протоках, які пакет визначає як суму лотів, а лоти є в `queue_lots.qty` («never dropped»).

## Як влаштована модель

Дія тижня = дія правил × поправка. Поправка — число від 0.5 до 2 на кожен слот, яке дає мережа. Останній шар
мережі ініціалізовано нулями, тож **ненавчений агент грає рівно як правила** (це питання 0, і воно пройдене:
парна різниця +0.0000). Якщо поправка не скінченна або робить потік від'ємним, тиждень грається самими правилами
— мережа не може зробити гірше за правила через арифметику, лише через те, чого навчилась.

Важливе обмеження, виміряне до початку: у типовий тиждень **60–66 % слотів правила лишають нулем**, а нуль
множенням не піднімеш. Тобто мультиплікативна поправка може лише перерозподіляти й підкручувати те, що правила
вже шлють. Чи потрібна адитивна поправка там, де правила шлють нуль, — окремий експеримент, а не рішення наперед.

## Файли

| файл | що робить |
| --- | --- |
| `features.py` | спостереження → три таблиці (вузли, ребра, слоти) + глобальні ознаки; усе нормоване «на своє» |
| `nets.py` | `SlotNet` (питання 1, без обміну повідомленнями) і `GraphNet` (питання 2, 2 раунди); спільна голова з нульовим стартом |
| `residual.py` | правила + мережа + перевірки; те саме і в навчанні, і в сабміті |
| `batching.py` | багато тижнів в один батч; тижні Small і Full можуть лежати поруч |
| `rollout.py` | один епізод у робочому процесі |
| `train.py` | PPO; один прогін = одне питання |
| `export.py` | тека сабміту: правила + мережа + ваги + `agent.py` |

Власний PPO, а не Stable-Baselines3: бриф вимагає мішати Small і Full з самого початку, а векторне середовище SB3
фіксує одну форму спостереження й дії на весь прогін (Small має 108 слотів дії, Full — 395).

## Як запустити

```bash
# окреме середовище з PyTorch (див. «Після перенесення»); команди в докстрингах модулів записані для машини сесії,
# де `uv run` не працював (uv 0.7.19 не знав Python 3.13.12): тут замість `PYTHONPATH=src .venv/bin/python` пиши
export UV_PROJECT_ENVIRONMENT=<тека поза репозиторієм>
uv run --extra rl python lab/anastasiia/rl_lab/train.py \
    --kind=slot --tasks=small --iters=120 --episodes_per_iter=72 --workers=9

# тека сабміту з прогону
uv run --extra rl python lab/anastasiia/rl_lab/export.py \
    --run=outputs/rl_lab/<прогін> --name=rl_slot --into=lab/anastasiia/rl_lab/agents

# рішення: парне порівняння з правилами на наборі підбору
uv run --extra rl python hub/eval/compare.py --base=agents/anastasiia_rules_v2 \
    --episodes=64 --entropy=111 --task=small --n_jobs=6 lab/anastasiia/rl_lab/agents/rl_slot
```

Важкі файли прогонів ідуть у `outputs/rl_lab/<прогін>/` (поза git): `settings.json`, `log.json`, `policy.pt`.

## Нагорода

Мінус вартість тижня, поділена на середню тижневу вартість naive тієї самої мережі (таблиця `ScaleReward` пакета:
67.0 млрд USD на Small, 89.9 млрд на Full). Тому тиждень Small і тиждень Full важать однаково і їх можна вчити
разом. Від вартості ще віднімається стала — середня тижнева вартість самих правил на цьому root; це нічого не
змінює в градієнті, але лишає повернення біля нуля, і критику майже нема чого відучувати.

Дисконт 0.997: наслідок рішення видно через 12–14 тижнів.
